# RAG Roadmap Setup — v1.2

## Goal

Generate a user-owned career roadmap through a real retrieval-augmented generation pipeline:

`profile + skill gap + target role -> query embedding -> Supabase pgvector retrieval -> validated LLM roadmap -> BullMQ worker -> Supabase persistence`

The deterministic `basic_template` roadmap remains available as an explicit fallback mode. It is never labeled as RAG.

## Architecture

### Frontend

- `/skill-gap` offers **Generate AI roadmap** and **Use basic plan** as separate actions.
- AI mode calls `POST /api/v1/roadmap/generate` with `generationMode: "rag"`.
- The API returns `202` with an AI job id.
- The frontend polls `GET /api/v1/roadmap/jobs/:jobId` until the job completes or fails.
- Completed AI jobs navigate to `/roadmap/:roadmapId`.
- The roadmap page displays whether the saved plan was generated by `rag` or `basic_template`.

### Backend

- Express verifies the Supabase bearer token.
- RAG requests are limited to 20/day/user through Redis.
- The backend creates an `ai_jobs` record and enqueues `roadmapGenerationQueue`.
- `roadmap-generation.worker.ts` processes the job outside the request lifecycle.
- The worker loads the authenticated user's `profiles` and `skill_analyses` data.
- The backend asks the AI service for a 1536-dimensional query embedding.
- Supabase RPC `match_knowledge_base_documents` performs cosine pgvector retrieval.
- Empty retrieval fails with `RAG_KNOWLEDGE_BASE_NOT_READY`; no template fallback is silently substituted.
- Retrieved documents and user facts are sent to the AI service for structured roadmap generation.
- The backend validates the returned document references again before persistence.
- Successful results are saved to `roadmaps`, `roadmap_weeks`, and `roadmap_tasks` with `generated_by = 'rag'`.
- Query text, embedding, retrieved ids/similarity scores, model names, latency, and failures are recorded in `rag_queries`.

### AI service

FastAPI exposes:

- `POST /embeddings`
- `POST /generate-roadmap`
- existing `POST /parse-resume`
- `GET /health`

The AI service uses OpenAI-compatible provider contracts configured through environment variables. It does not contain a fake model response.

`/generate-roadmap` validates output with Pydantic and rejects:

- invalid JSON
- mismatched `duration_weeks`
- non-sequential weeks
- empty weeks/tasks
- knowledge-base ids that were not in the retrieved context

## Required environment variables

```env
AI_SERVICE_URL=http://localhost:8000

EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_API_KEY=
EMBEDDING_MODEL=
RAG_EMBEDDING_DIMENSION=1536

LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=
LLM_MODEL=
AI_PROVIDER_TIMEOUT_SECONDS=45
```

`EMBEDDING_BASE_URL` and `LLM_BASE_URL` may point to another OpenAI-compatible provider.

The current database column is `vector(1536)`, so the configured embedding model must return exactly 1536 values. A dimension mismatch fails closed.

## Index the knowledge base

Knowledge-base vector indexing is an explicit admin action so model/API credentials are never baked into migrations.

Protected admin endpoints:

- `GET /api/v1/admin/knowledge-base/index-status`
- `POST /api/v1/admin/knowledge-base/reindex`

Example request body:

```json
{
  "limit": 20,
  "force": false
}
```

`force: false` indexes only active documents whose embedding is null. Existing document metadata is preserved while embedding metadata is added.

Run batches until `pending` becomes `0`.

## Roadmap APIs

Protected endpoints under `/api/v1/roadmap`:

- `POST /generate`
  - `generationMode: "basic_template"` -> synchronous `201`
  - `generationMode: "rag"` -> queued `202`
- `GET /jobs/:jobId`
- `GET /`
- `GET /:roadmapId`
- `PATCH /:roadmapId`
- `PATCH /:roadmapId/tasks/:taskId`
- `PATCH /:roadmapId/tasks/:taskId/complete`
- `DELETE /:roadmapId`

## Required data sources

RAG generation uses only:

- `profiles` — target role, current profile skills, career goal
- `skill_analyses` — current, missing, matched, and recommended skills
- `knowledge_base_documents` — retrieved context
- the configured embedding/LLM providers

The model must not invent personal education, employers, projects, certifications, achievements, or other unsupported user claims.

## Docker Compose

The root compose file now runs:

- `backend`
- `resume-worker`
- `roadmap-worker`
- `ai-service`
- `redis`

Supabase remains managed externally.

The backend/worker containers use Node 22 to match CI.

## Validation

Product CI now validates all three codebases:

```text
backend: npm ci -> typecheck -> tests -> build
frontend: npm ci -> typecheck -> tests -> build
ai-service: pip install -> compileall -> pytest
```

A live end-to-end RAG run additionally requires:

1. Supabase migrations applied to a real project.
2. Seed knowledge-base rows present.
3. Embedding and LLM provider credentials configured.
4. Knowledge-base indexing completed.
5. Redis, backend, AI service, and roadmap worker running.

Without provider credentials or indexed vector content, AI mode fails explicitly and the separate basic-plan action remains available.
